Le workflow démarre…

Le workflow s’arrête à l’étape « Validation » et attend votre clic, comme dans l’application.

    Chacun fait ce qu’il fait de mieux

    Un projet fictif, une réunion hebdomadaire, un COPIL dans 6 jours. Le workflow répartit le travail selon une règle simple : ce qui s’exécute est piloté par Python, ce qui demande de lire est confié à l’IA, ce qui engage est décidé par vous.

    Python

    Ce qui s’exécute

    • Enchaîne les étapes, les branches et les reprises
    • Lance commandes, scripts, appels réseau et écritures de fichiers
    • Calcule quand il le faut : indicateurs, statut VERT, ORANGE ou ROUGE

    CSAgent

    Ce qui demande de lire

    • Risques, actions et décisions tirés de notes libres
    • Rédaction du rapport pour la direction
    • Note d’escalade, seulement si le statut est ROUGE

    Vous

    Ce qui engage

    • Relecture du rapport
    • Approuver ou rejeter la diffusion
    • Sans réponse, la diffusion est rejetée

    L’IA ne calcule jamais un chiffre. Elle lit et rédige à partir de résultats déjà calculés.

    Suivez chaque étape, sans quitter la page

    L’application montre le graphe, l’état de chaque étape, le YAML en cours d’exécution et le journal en direct. Ici, le workflow attend la décision du chef de projet.

    • Graphe vivantÉtapes terminées, en cours, à venir et branches, jamais signalées par la couleur seule.
    • YAML relié au grapheCliquez une étape : son bloc de YAML est surligné.
    • Journal en directChaque événement arrive à l’écran, y compris les outils de CSAgent : read_file, write_file avec leur chemin.

    Un workflow, c’est un fichier texte

    Les étapes sont décrites en YAML : lisible, versionnable, relisible par n’importe qui. Une condition et une validation humaine tiennent chacune en quelques lignes. CSAgent agit avec ses propres outils (lire, écrire et modifier des fichiers) : il suffit de les demander dans le prompt.

    • ?
      Branche conditionnelleAvec skip_if, l’escalade n’est écrite que si le statut est ROUGE.
    • ✓
      Décision humaineAvec human_approval, vous choisissez la suite : diffuser ou annuler.
    • { }
      Résultats réutilisablesChaque étape reprend les sorties des précédentes avec {{id}}.
    # Extrait abrégé du workflow COPIL
- id: escalade
  type: agent
  skip_if: "'{{statut.output}}' != 'ROUGE'"
  prompt: "Rédige une note d'escalade au sponsor."

- id: validation
  type: human_approval
  message: "Statut : {{statut.output}}. Diffuser ?"
  on_approve: relecture
  on_reject: annule

    Pour les développeurs : des routines fiables, un humain aux commandes

    Python orchestre les tests, git et vos scripts, étape après étape. CSAgent n’intervient que là où il faut lire du code. Voici le workflow dev-fix-tests, livré avec CSFlow.

    1. Lancer les testsPython · unittest
    2. Corriger le codeCSAgent · sans toucher aux tests
    3. Relancer les testsPython · git diff
    4. ValiderVous · commit ou annulation
    5. CommitterPython · git
    • Corriger les tests qui échouentCSAgent reçoit l’erreur exacte des tests. Si tout passe déjà, l’étape est ignorée avec skip_if.
    • Préparer une revue de codegit diff rassemble les faits, CSAgent rédige la synthèse, vous relisez avant de la publier.
    • Rédiger des notes de versiongit log extrait les commits, CSAgent écrit le texte, rien n’est publié sans votre accord.
    • Trier des logs d’incidentUne commande ou un appel http récupère les logs. L’escalade n’a lieu que si la gravité est haute.
    • Versionner vos routinesUn workflow est un fichier YAML : relisible dans une pull request et partageable avec l’équipe.
    • Contrôler avant de lancerpython engine.py --check mon.yaml signale les erreurs de syntaxe ou d’étapes avant l’exécution, y compris dans un script de CI.

    En cas de rejet, git checkout remet le code dans son état de départ. Le workflow de démonstration travaille dans son propre dépôt git, jamais dans votre projet.

    Lancez vos workflows depuis CSAgent

    Avec l’option CSFlow --mcp, CSFlow s’ouvre sans interface et CSAgent pilote vos workflows à votre place : vous demandez, il lance et suit le déroulement.

    1. Vous demandez« Lance demo_report »
    2. CSAgentvous demande la permission
    3. CSFlowexécute le workflow, étape par étape
    4. CSAgent (worker)traite les étapes agent
    • Quatre actionsLister les workflows, les vérifier, en lancer un, suivre son état jusqu’à la fin.
    • Les longs workflows tiennentUn workflow de plusieurs minutes est suivi par appels successifs : rien n’est coupé au bout d’une minute.
    • La validation humaine reste chez vousUn workflow qui demande votre accord est refusé : vous le lancez depuis l’interface et vous approuvez vous-même.
    • Un workflow à la fois, dans un seul dossierSeuls les fichiers du dossier workflows sont accessibles.

    Les étapes shell et python d’un workflow ne passent pas par le filtre de commandes de CSAgent : réservez ce mode à des workflows et à un dossier de confiance. Mise en route : start_csagent.bat, détaillée dans la documentation.

    Conçu pour rester sous contrôle

    Un outil d’automatisation n’a de valeur que si on peut lui faire confiance. CSFlow place les garde-fous dans le workflow lui-même.

    • ✓
      Des chiffres calculés, pas devinésLes indicateurs sortent d’un calcul Python, jamais d’un modèle de langage.
    • ✓
      Validation avant diffusionSans réponse sous 10 minutes, l’étape est rejetée.
    • ✓
      Écritures de l’IA limitéesCSAgent n’écrit que dans son dossier courant.
    • ✓
      YAML vérifié avant exécutionUne clé inconnue ou une étape manquante est signalée avant le lancement.
    • ✓
      Accessible au clavierListe d’étapes navigable, focus visible, textes lisibles et agrandissables.
    • ✓
      Local sur votre posteApplication de bureau Windows, clé d’API gardée dans votre environnement.

    Démarrez en trois commandes

    Depuis les sources : Python 3.10 ou plus récent, sous Windows, dans le dossier workflow. Avec l’exe compilé (CSFlow.exe), aucun Python n’est à installer : même les scripts Python de vos workflows tournent sur l’interpréteur embarqué.

    1. Installer les dépendances

    pip install -r requirements.txt

    2. Lancer CSAgent avec votre clé

    set ALBERT_API_KEY=ta-cle
start_agent.bat

    3. Ouvrir l’application

    python app.py

    Automatisez le travail. Gardez la décision.

    Regardez le workflow COPIL de bout en bout, ou ouvrez la documentation pour écrire le vôtre.
