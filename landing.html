Le workflow démarre…

Le workflow s’arrête à l’étape « Validation » et attend votre clic, comme dans l’application.

    Chacun fait ce qu’il fait de mieux

    Un projet fictif, une réunion hebdomadaire, un COPIL dans 6 jours. Le workflow répartit le travail selon une règle simple : ce qui doit être exact est calculé, ce qui demande de lire est confié à l’IA, ce qui engage est décidé par vous.

    Python

    Ce qui doit être exact

    • Valeur acquise, CPI, retards, dérive
    • Statut global : VERT, ORANGE ou ROUGE
    • Écriture des fichiers, appels réseau, commandes

    CSAgent

    Ce qui demande de lire

    • Risques, actions et décisions tirés de notes libres
    • Rédaction du rapport pour la direction
    • Note d’escalade, seulement si le statut est ROUGE

    Vous

    Ce qui engage

    • Relecture du rapport
    • Approuver ou rejeter la diffusion
    • Sans réponse, la diffusion est rejetée

    L’IA ne calcule jamais un chiffre. Elle lit et rédige à partir de résultats déjà calculés.

    Suivez chaque étape, sans quitter la page

    L’application montre le graphe, l’état de chaque étape, le YAML en cours d’exécution et le journal en direct. Ici, le workflow attend la décision du chef de projet.

    • Graphe vivantÉtapes terminées, en cours, à venir et branches, jamais signalées par la couleur seule.
    • YAML relié au grapheCliquez une étape : son bloc de YAML est surligné.
    • Journal en directChaque événement du moteur arrive à l’écran à mesure qu’il se produit.

    Un workflow, c’est un fichier texte

    Les étapes sont décrites en YAML : lisible, versionnable, relisible par n’importe qui. Une condition et une validation humaine tiennent chacune en quelques lignes.

    • ?
      Branche conditionnelleAvec skip_if, l’escalade n’est écrite que si le statut est ROUGE.
    • ✓
      Décision humaineAvec human_approval, vous choisissez la suite : diffuser ou annuler.
    • { }
      Résultats réutilisablesChaque étape reprend les sorties des précédentes avec {{id}}.
    # Extrait abrégé du workflow COPIL
- id: escalade
  type: agent
  skip_if: "'{{statut.output}}' != 'ROUGE'"
  prompt: "Rédige une note d'escalade au sponsor."

- id: validation
  type: human_approval
  message: "Statut : {{statut.output}}. Diffuser ?"
  on_approve: relecture
  on_reject: annule

    Conçu pour rester sous contrôle

    Un outil d’automatisation n’a de valeur que si on peut lui faire confiance. CSFlow place les garde-fous dans le workflow lui-même.

    • ✓
      Des chiffres calculés, pas devinésLes indicateurs sortent d’un calcul Python, jamais d’un modèle de langage.
    • ✓
      Validation avant diffusionSans réponse sous 10 minutes, l’étape est rejetée.
    • ✓
      Écritures de l’IA limitéesCSAgent n’écrit que dans son dossier courant.
    • ✓
      YAML vérifié avant exécutionUne clé inconnue ou une étape manquante est signalée avant le lancement.
    • ✓
      Accessible au clavierListe d’étapes navigable, focus visible, textes lisibles et agrandissables.
    • ✓
      Local sur votre posteApplication de bureau Windows, clé d’API gardée dans votre environnement.

    Démarrez en trois commandes

    Python 3.10 ou plus récent, sous Windows, dans le dossier workflow.

    1. Installer les dépendances

    pip install -r requirements.txt

    2. Lancer CSAgent avec votre clé

    set ALBERT_API_KEY=ta-cle
start_agent.bat

    3. Ouvrir l’application

    python app.py

    Automatisez le travail. Gardez la décision.

    Regardez le workflow COPIL de bout en bout, ou ouvrez la documentation pour écrire le vôtre.
